# Руководство по разработке (Development Guide)
Этот документ описывает процесс настройки окружения, сборки и внесения изменений в проект **MeraluaLib**.
## 📋 Требования
- **Git** — система контроля версий.
- **Bash** — для запуска скриптов сборки (встроен в Linux/macOS, для Windows используйте Git Bash или WSL).
- **Lua** (опционально) — для тестирования кода локально.
## ⚙️ Настройка окружения
1. Склонируйте репозиторий:
   ```bash
   git clone git@gl.mera.local:acs/meralualib.git
   cd meralualib
   ```
2. Убедитесь, что скрипт сборки исполняемый:
   ```bash
   chmod +x build.sh
   ```
## 🏗 Процесс сборки
Проект использует систему токенов для подстановки версии библиотеки при сборке.
### Как это работает
В исходных файлах `.lua` используются специальные маркеры:
```lua
-- @build_token: LIB_PATH_VERSION
local lib_path = "meralualib.src."
```
При запуске `build.sh`:
1. Скрипт находит все файлы с комментарием-токеном `@build_token: LIB_PATH_VERSION`.
2. Удаляет строку с комментарием-токеном.
3. Заменяет следующую строку на актуальный путь версии библиотеки (например, `meralualib.v1_0_0.`).
### Запуск сборки
```bash
./build.sh
```
Результат сборки появится в папке `build/<версия>/`.
> **Важно:** Никогда не меняйте строку `local lib_path = "meralualib.src."` вручную. Оставьте её как есть, сборка автоматически подставит нужную версию.
## Правила импорта модулей внутри библиотеки
Перед импортом модулей используйте комментарий с билд-токеном `-- @build_token: LIB_PATH_VERSION` и отладочный относительный путь до библиотеки:
```lua
-- @build_token: LIB_PATH_VERSION
local lib_path = "meralualib.src."
```
Далее можно импортировать модули библиотеки следующим образом:
```lua
local timers = require(lib_path .. "timers")
```
## Настройка окружения
### Настройка переменной окружения LUA_PATH для отладки исходного кода в Windows
1. В поиске ввести "изменение системных переменных среды".
2. Выбрать "Переменны среды...".
3. в окне "Системные переменные" найти переменную "LUA_PATH" и нажать изменить (при отсутствии переменной нажать создать).
4. Ввести желаемое расположение до исходного кода библиотеки, например:

| - | - |
|-------------|-------------|
| Имя переменной       | LUA_PATH       |
| Значение переменной       | `;;e:\dev\?.lua;e:\dev\?\init.lua`       |

Двойная точка с запятой впереди обязательна - это путь по умолчанию, вшитый в интерпретатор lua при его сборке в СИАМ.

После этого можете разместить исходный код библиотеки (папку `meralualib`), как в примере выше, в папку `e:\dev\` - встроенный интерпретатор lua в СИАМ будет обращаться по этому пути для поиска `meralualib`.
## 🧪 Тестирование
Перед отправкой изменений убедитесь, что:
- Сборка проходит без ошибок.
- Все файлы содержат корректные токены (если вы добавляете новый модуль).
- Код соответствует стилю проекта.
## 📝 Правила оформления кода
- Используйте отступы в 4 пробела.
- Избегайте лишних пустых строк.
- Добавляйте комментарии только там, где логика неочевидна.
- При импорте модули должны содержать токен `-- @build_token: LIB_PATH_VERSION` перед строкой с `lib_path`.
## 🔄 Внесение изменений
1. Создайте новую ветку:
   ```bash
   git checkout -b feature/my-feature
   ```
2. Внесите изменения и закоммитьте их:
   ```bash
   git add .
   git commit -m "feat: описание изменений"
   ```
3. Отправьте ветку на сервер:
   ```bash
   git push origin feature/my-feature
   ```
4. Создайте Pull Request.
