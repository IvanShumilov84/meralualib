## Глобальные настройки

Объект `am.manager_settings` содержит глобальные настройки менеджера. Изменяется **до** первого вызова `am:upd()`.

```lua
am.manager_settings.alarm_appearance = am.ALARM_APPEARANCE.FLASH
am.manager_settings.msg_color.error = 0x000000FF  -- красный
```

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `alarm_appearance` | `ALARM_APPEARANCE_VALUE` | `ALARM_APPEARANCE.FLASH` | Визуальный способ появления тревоги |
| `create_tags` | `boolean` | `true` | Создавать каналы таблиц в СИАМ |
| `msg_color` | `table` | — | Цвета тревог (см. ниже) |

### Цвета тревог `msg_color`

| Поле | Тип | По умолчанию (C++ Hex) | Описание |
|------|-----|------------------------|----------|
| `error` | `integer` | `0x00424CEB` | Цвет активной тревоги класса ERROR (красный) |
| `warn` | `integer` | `0x00008BFF` | Цвет активной тревоги класса WARN (оранжевый) |
| `info` | `integer` | `0x0033FEFE` | Цвет активной тревоги класса INFO (жёлтый) |
| `unack` | `integer` | `0x00A6A6A6` | Цвет фона неквитированной тревоги (серый) |

> ⚠️ Формат цвета — `0x00BBGGRR` (C++ Hex, порядок байт: B-G-R).

## Перечислители

### `am.LOGIC` — способ наблюдения за событием

| Значение | Код | Описание |
|----------|-----|----------|
| `DISCRETE` | `0` | Дискретный канал (0 / ≠0) |
| `ANALOG` | `1` | Аналоговый канал с уставками |
| `CHANGE` | `2` | Любое изменение события *(в разработке)* |
| `EVENT` | `3` | Событие `true`/`false` или число >0/0|
| `CS_CLIENT` | `4` | Повторение состояния из Кодесис |

### `am.ALARM_CLASS` — класс тревоги

| Значение | Код | Описание |
|----------|-----|----------|
| `ERROR` | `0` | Авария (красный) |
| `WARN` | `1` | Предупреждение (оранжевый) |
| `INFO` | `2` | Информирование (жёлтый) |

### `am.CONFIRM_METHOD` — способ подтверждения тревоги

| Значение | Код | Описание | Статус |
|----------|-----|----------|--------|
| `ACK` | `0` | Квитирование | ⚠️ в разработке |
| `REP` | `1` | Деактивация | ✅ |
| `ACK_REP` | `2` | Подтверждение деактивированной или деактивация квитированной | ⚠️ в разработке |
| `REP_ACK` | `3` | Подтверждение деактивированной | ✅ |
| `ACK_REP_ACK` | `4` | Подтверждение деактивированной (опционально квитированной) | ⚠️ в разработке |

### `am.LIMIT_TYPE` — тип ограничения для `LOGIC.ANALOG`

| Значение | Код | Описание |
|----------|-----|----------|
| `LOW` | `0` | Ограничение снизу |
| `HIGH` | `1` | Ограничение сверху |
| `LOW_HIGH` | `2` | Ограничение с двух сторон |

### `am.CS_ALARM_STATE` — состояние тревоги из Кодесис

| Значение | Код | Описание |
|----------|-----|----------|
| `NOT_DEFINED` | `255` | Неопределено |
| `NORMAL` | `0` | Тревога неактивна |
| `PENDING` | `1` | Условие активно, тревога неактивна |
| `ACTIVE` | `2` | Тревога активна |
| `WAITING_FOR_CONFIRMATION` | `3` | Неактивна, требует квитирования |
| `ACTIVE_ACKNOWLEDGED` | `4` | Активна и квитирована |

### `am.ALARM_APPEARANCE` — визуальный эффект появления

| Значение | Код | Описание |
|----------|-----|----------|
| `STATIC` | `0` | Тревога появляется сразу |
| `BLINK` | `1` | Мигание при появлении (6 смен цвета, период 0.2 с) |
| `FLASH` | `2` | Плавная вспышка от белого к базовому цвету (~1.5 с) |

## Класс `am.Atable`

Класс таблицы тревог. Наследует все поля конфигурации `AlarmManager.AtableConfig` и добавляет методы управления.

### `am.Atable:new(conf?)` → `M.Atable`

Создаёт экземпляр таблицы тревог.

**Параметры:**

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `conf` | `AlarmManager.AtableConfig` | Нет | Конфигурация таблицы (по умолчанию из `_conf`) |

**Возвращает:** экземпляр `M.Atable`.

**Особенности:**
- Регистрация таблицы откладывается до первого вызова `am:upd()`.
- `table_id` должен быть установлен **до** вызова `am:upd()`.
- Нельзя помещать вызов `new()` внутрь `if`.

```lua
local atable = am.Atable:new{
    table_id = 1,
    module_name = "Система_01.Таблица_01",
}
```

### `atable:alarm(args)` → `AlarmManager.AlarmArgs`

Регистрирует тревогу в таблице.

**Параметры:**

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `args` | `AlarmManager.AlarmArgs` | Нет | Структура тревоги |

**Возвращает:** `AlarmManager.AlarmArgs` — ссылку на созданную тревогу (для последующего изменения полей).

**Важно:**
- ❌ Нельзя помещать вызов `atable:alarm{}` внутрь `if` — это может привести к остановке скрипта в рантайме
  при проверке типов параметров и недопустимых параметров.
- ✅ Можно изменять поля возвращённого объекта после вызова.

```lua
-- Передача параметров при регистрации тревоги
atable:alarm{  -- Круглые скобки метода alarm можно опустить
    logic = am.LOGIC.EVENT,
    class = am.ALARM_CLASS.ERROR,
    msg = "Авария",
    event = getValue("signal") > 0
}
```

```lua
-- Изменение параметров после регистрации тревоги
local alarm = atable:alarm{}  -- Допустимы круглые скобки atable:alarm()
alarm.logic = am.LOGIC.EVENT
alarm.class = am.ALARM_CLASS.ERROR
alarm.event = getValue("signal") > 0
alarm.msg = "Авария"
```

```lua
-- Спешанный тип настройки параметров с передачей при регистрации и после регистрации тревоги
local alarm = atable:alarm{
    logic = am.LOGIC.EVENT,
    class = am.ALARM_CLASS.ERROR,
    msg = "Авария",
}
alarm.event = getValue("signal") > 0
```

## Метод `am:upd()`

Циклическое обновление менеджера. **Должен вызываться один раз в `lua_main()` до регистрации тревог.**

```lua
function lua_main()
    am:upd()        -- ← в самом начале
    -- ... регистрация тревог ...
end
```

**Что делает `am:upd()`:**
1. Регистрирует отложенные таблицы (`_pending_tables`).
2. Проверяет конфигурации таблиц.
3. Создаёт переменные окружения (при первом вызове).
4. Создаёт каналы количества тревог в СИАМ (при первом вызове).
5. Запускает таймер задержки старта (~1 с).
6. Обновляет таймеры визуальных эффектов.
7. Обрабатывает список тревог.
8. Очищает список тревог (он формируется заново в каждом цикле).

> ⚠️ Список тревог **обнуляется** в конце каждого вызова `am:upd()`. Это значит, что все тревоги должны регистрироваться **в каждом цикле** `lua_main()`.

| Поле | Тип | По умолчанию | Описание |

| `class` | `ALARM_CLASS_VALUE` | `ALARM_CLASS.ERROR` | Класс тревоги |

| `cs_alarm_state` | `CS_ALARM_STATE_VALUE` | `CS_ALARM_STATE.NORMAL` | Состояние из Кодесис при `LOGIC.CS_CLIENT` |
| `cs_ack` | `string` | `""` | Канал квитирования при `LOGIC.CS_CLIENT` |
| `analog` | `AlarmManager.AlarmAnalogConfig` | — | Переопределение настроек аналоговой тревоги |

## Автоматически генерируемые каналы

Модуль автоматически создаёт каналы количества тревог в СИАМ по шаблону:

```
alarm_manager.table_id_<ID>.<статус>.<класс>
```

### Имена каналов

| Статус | Префикс | Описание |
|--------|---------|----------|
| Активные | `alarm_qty` | Количество активных тревог |
| Неквитированные | `unack_qty` | Количество неквитированных тревог |

| Класс | Суффикс |
|-------|---------|
| ERROR | `error` |
| WARN | `warn` |
| INFO | `info` |
| Все классы | `all_alarm` |

### Примеры имён каналов

Для таблицы с `table_id = 1`:

```
alarm_manager.table_id_1.alarm_qty.error       -- количество активных аварий
alarm_manager.table_id_1.alarm_qty.warn        -- количество активных предупреждений
alarm_manager.table_id_1.alarm_qty.info        -- количество активных информирований
alarm_manager.table_id_1.alarm_qty.all_alarm   -- общее количество активных тревог
alarm_manager.table_id_1.unack_qty.error       -- количество неквитированных аварий
alarm_manager.table_id_1.unack_qty.all_alarm   -- общее количество неквитированных
```

Для главной таблицы (`table_id = -1`) — суммарные значения по всем таблицам:

```
alarm_manager.table_id_-1.alarm_qty.error
alarm_manager.table_id_-1.unack_qty.all_alarm
...
```

### Канал кнопки квитирования (⚠️ в разработке)

Если в конфигурации таблицы `ack_btn = true`, создаётся канал:

```
alarm_manager.table_id_<ID>.acknow
```

## Переменные окружения

Модуль использует переменные окружения для хранения глобального состояния между скриптами.

| Имя | Тип | Описание |
|-----|-----|----------|
| `#alarm_manager__alarm_id_counter` | `integer` | Счётчик сквозных ID тревог |
| `#alarm_manager__total_alarms` | `integer` | Общее количество зарегистрированных тревог |
| `#alarm_manager__script_id` | `integer` | ID текущего вызывающего скрипта |
| `#alarm_manager__tbl_ids` | `string` | Список ID таблиц через `\|` (например, `"1\|2\|5"`) |

> 💡 Переменные окружения инициализируются при первом запуске после загрузки СИАМ и сохраняются между сессиями.

## Валидация параметров

Модуль выполняет строгую проверку параметров тревог. При нарушении — `assert` с подробным сообщением.

### Проверки типов

- Все параметры должны соответствовать типам из `_alarm`.
- Непредусмотренные поля в конфигурации вызывают ошибку.

### Проверки значений

| Параметр | Условие |
|----------|---------|
| `prior` | `1 ≤ prior ≤ 1000` |
| `logic` | Должен принадлежать `am.LOGIC` |
| `class` | Должен принадлежать `am.ALARM_CLASS` |
| `confirm_method` | Должен принадлежать `am.CONFIRM_METHOD` |
| `limit_type` | Должен принадлежать `am.LIMIT_TYPE` |
| `cs_alarm_state` | Должен принадлежать `am.CS_ALARM_STATE` |
| `hyst_low`, `hyst_high` | `≥ 0` |
| `low`, `high` при `LOW_HIGH` | `low ≤ high` |

### Проверки каналов (для `LOGIC.ANALOG`)

- `channel` не должен быть пустым.
- `channel` должен существовать в СИАМ.
- Если `get_limit_from_chan = true`:
  - `ch_low` и/или `ch_high` не должны быть пустыми (в зависимости от `limit_type`).
  - Каналы `ch_low`/`ch_high` должны существовать в СИАМ.
- Если канал неисправен (`getEstimate` возвращает статус ≠ 0), тревога автоматически переводится в `LOGIC.EVENT` с диагностическим сообщением.

### Пример сообщения об ошибке

```
alarm.id = 5 (alarm.msg = 'Температура'): parameter 'prior' value (= 2000) must be within 1..1000
```

## Визуальные эффекты

### `ALARM_APPEARANCE.STATIC`

Тревога появляется сразу с базовым цветом класса.

### `ALARM_APPEARANCE.BLINK`

При появлении тревога мигает 6 раз (период 0.2 с), чередуя базовый цвет и белый.

### `ALARM_APPEARANCE.FLASH`

При появлении тревога плавно меняет цвет от белого к базовому цвету класса за ~1.5 с (количество шагов зависит от периода скрипта).

> 💡 Количество шагов вспышки рассчитывается автоматически: `_COLOR_QTY = _ALARM_FLASH_TIME / _SCRIPT_PERIOD`.

## Состояния тревоги в СИАМ

Внутри менеджера тревога может находиться в одном из трёх состояний:

| Состояние | Код | Описание |
|-----------|-----|----------|
| `ACTIVE` | `0` | Активная |
| `NOT_ACTIVE` | `1` | Неактивная (после деактивации, до полного удаления) |
| `ACK` | `2` | Квитированная |

### Лейблы состояний в журнале СИАМ

| Состояние | Лейбл |
|-----------|-------|
| Активная | `[Активна]` |
| Квитированная | `[Квитирована]` |
| Неактивная | `[Неактивна]` |
| Неактивная, неквитированная | `[Неактивна, неквитирована]` |
